# Oracle DDL ve script standardı

> Başlangıç standardıdır. Projede yerleşik bir script klasörü, numaralandırma veya migration aracı (Flyway, Liquibase, EF Core migration)
> varsa (proje haritası `veritabani.md`) onu kullan; bu dosyadaki dosya düzeni yalnızca proje bir düzen tanımlamıyorsa geçerlidir.

## 1. Nesne isimlendirme
Tümü **büyük harf**, kelimeler `_` ile ayrılır, tırnaklı (case-sensitive) isim yok, en fazla 30 karakter.

| Nesne | Kural | Örnek |
|---|---|---|
| Tablo | İngilizce, çoğul | `ORDERS`, `ORDER_LINES` |
| Kolon | İngilizce, tekil | `ORDER_DATE`, `CUSTOMER_ID` |
| Primary key | `PK_<TABLO>` | `PK_ORDERS` |
| Foreign key | `FK_<TABLO>_<HEDEF_TABLO>` | `FK_ORDER_LINES_ORDERS` |
| Unique | `UK_<TABLO>_<KOLON>` | `UK_ORDERS_ORDER_NO` |
| Check | `CK_<TABLO>_<KOLON>` | `CK_ORDERS_STATUS` |
| Index | `IX_<TABLO>_<KOLON(LAR)>` | `IX_ORDERS_CUSTOMER_ID` |
| Sequence | `SEQ_<TABLO>` | `SEQ_ORDERS` |
| View | `VW_<AD>` | `VW_ACTIVE_ORDERS` |
| Trigger | bkz. `oracle-trigger` | `TRG_ORDERS_BIU` |
| Package | bkz. `oracle-plsql` | `PKG_ORDERS` |

Projede tablo adları tekil veya Türkçe ise projeye uy (proje haritası "Projeye özgü kurallar").

## 2. Veri tipleri
| İhtiyaç | Tip | Not |
|---|---|---|
| Metin | `VARCHAR2(n CHAR)` | **`CHAR` semantiği zorunlu.** `VARCHAR2(50)` varsayılan olarak 50 *byte*'tır; Türkçe karakterler (ğ, ş, İ) birden fazla byte tutar ve ORA-12899 verir. |
| Uzun metin (> 4000 byte) | `CLOB` | |
| Tam sayı ID | `NUMBER(19)` | C# `long` |
| Küçük tam sayı | `NUMBER(10)` | C# `int` |
| Para / miktar | `NUMBER(18,2)` (ihtiyaca göre) | Asla `FLOAT`/`BINARY_DOUBLE` |
| Bayrak (evet/hayır) | `NUMBER(1) DEFAULT 0 NOT NULL` + `CHECK (KOLON IN (0,1))` | Projede `CHAR(1)` `'Y'/'N'` kullanılıyorsa ona uy |
| Tarih + saat | `TIMESTAMP` | Sadece gün gerekiyorsa `DATE` (Oracle `DATE` de saat tutar) |
| Durum/tip kodu | `VARCHAR2(30 CHAR)` + `CHECK` veya lookup tablosu | |

- Boş string Oracle'da NULL'dur; "boş olamaz" kuralı `NOT NULL` ile verilir.
- Her kolonun NULL olup olamayacağı bilinçli seçilir; varsayılan NOT NULL düşün.

## 3. Standart kolonlar
Yeni her iş tablosunda:
```sql
ID          NUMBER(19) GENERATED BY DEFAULT ON NULL AS IDENTITY,
-- ... iş kolonları ...
CREATED_AT  TIMESTAMP          NOT NULL,
CREATED_BY  VARCHAR2(100 CHAR) NOT NULL,
UPDATED_AT  TIMESTAMP,
UPDATED_BY  VARCHAR2(100 CHAR),
CONSTRAINT PK_<TABLO> PRIMARY KEY (ID)
```
- Audit kolonları `oracle-trigger` Şablon A ile doldurulur (veya uygulama dolduruyorsa projeye uy).
- Oracle 12c öncesi veya projede sequence deseni varsa: `SEQ_<TABLO>` + `DEFAULT SEQ_<TABLO>.NEXTVAL`.

## 4. Constraint ve index
- Constraint'ler isimsiz bırakılmaz (Oracle'ın `SYS_C00123` isimleri yasak); hepsi Bölüm 1'e göre isimlenir.
- **Her foreign key kolonuna index açılır.** Oracle FK'lere otomatik index açmaz; indexsiz FK, üst tabloda silme/güncellemede tablo kilidine yol açar.
- Sorgularda sık filtrelenen kolonlar için index düşün; ama her kolona index açma (yazma maliyeti).
- Her tablo ve kolon için `COMMENT ON` yazılır:
  ```sql
  COMMENT ON TABLE ORDERS IS 'Müşteri siparişleri';
  COMMENT ON COLUMN ORDERS.STATUS IS 'Sipariş durumu: NEW, APPROVED, SHIPPED, CANCELLED';
  ```

## 5. Script dosyaları
Projede düzen yoksa:
```
db/scripts/
├── 20261118_01_orders_add_status_changed_at.sql
├── 20261118_01_orders_add_status_changed_at.rollback.sql
├── 20261118_02_trg_orders_biu.sql
└── 20261118_02_trg_orders_biu.rollback.sql
```
- Ad: `<YYYYMMDD>_<sıra>_<kısa_açıklama>.sql`, küçük harf. Her script'in bir `.rollback.sql` eşi olur.
- Bir script tek bir mantıksal değişiklik yapar.
- Script'in başında yorum: amaç, task/görev ID'si, tarih.
- PL/SQL blokları ve `CREATE OR REPLACE` nesneleri `/` ile biter.
- Script'te `COMMIT` yalnızca veri değiştiren (DML) script'lerin sonunda bulunur; DDL zaten örtük commit yapar.

## 6. Tekrar çalıştırılabilir (idempotent) script
Script iki kez çalışırsa hata vermemeli. DDL'i sözlük kontrolüyle sar:
```sql
-- Görev: GOREV-123 | ORDERS tablosuna STATUS_CHANGED_AT eklenir
DECLARE
  v_count NUMBER;
BEGIN
  SELECT COUNT(*) INTO v_count
    FROM USER_TAB_COLUMNS
   WHERE TABLE_NAME = 'ORDERS' AND COLUMN_NAME = 'STATUS_CHANGED_AT';

  IF v_count = 0 THEN
    EXECUTE IMMEDIATE 'ALTER TABLE ORDERS ADD (STATUS_CHANGED_AT TIMESTAMP)';
    EXECUTE IMMEDIATE q'[COMMENT ON COLUMN ORDERS.STATUS_CHANGED_AT IS 'Durumun son değiştiği zaman']';
  END IF;
END;
/
```
- Tablo için `USER_TABLES`, index için `USER_INDEXES`, constraint için `USER_CONSTRAINTS`, sequence için `USER_SEQUENCES` kontrol edilir.
- Nesneler başka bir şemadaysa `ALL_*` görünümleri ve `OWNER` koşulu kullanılır.

## 7. Büyük tablolar ve veri değişikliği
- Büyük tabloya NOT NULL kolon eklerken `DEFAULT` ile ekle (Oracle 11g+ bunu tabloyu yeniden yazmadan yapar).
- Milyonlarca satırı güncelleyen veri script'leri tek seferde değil, parti parti (örn. 10.000 satır) ve commit'lerle çalışır.
- `DROP TABLE`, `DROP COLUMN`, `TRUNCATE` içeren script'ler için rollback, önceden alınmış yedek tablodan geri yüklemeyi içerir (`CREATE TABLE X_BAK_<YYYYMMDD> AS SELECT ...`). Bunu kullanıcıya açıkça bildir.
- Grant ve synonym gerekiyorsa projedeki düzene göre aynı script'e veya ayrı bir script'e eklenir.

## Kontrol listesi
Zorunlu:
- [ ] İsimler Bölüm 1'e uygun, büyük harf, ≤ 30 karakter, isimsiz constraint yok
- [ ] Metin kolonları `VARCHAR2(n CHAR)`
- [ ] Para/miktar `NUMBER(p,s)`, `FLOAT` yok
- [ ] Yeni tabloda PK ve audit kolonları var
- [ ] Her FK kolonunda index var
- [ ] Her script'in rollback eşi var
- [ ] Script tekrar çalıştırılabilir
- [ ] Yıkıcı işlemde (DROP/TRUNCATE) yedek adımı var

Tavsiye:
- [ ] Tablo ve kolonlarda `COMMENT ON` var
- [ ] Script başında amaç/görev yorumu var
- [ ] Büyük veri değişiklikleri parti parti
