# Oracle trigger standardı

> Başlangıç standardıdır; ekip kararlarına göre güncellenir. Amaç: farklı kişilerin yazdığı trigger'ların **aynı yapıda** olması.
> Projede yerleşik bir trigger deseni varsa (proje haritası `veritabani.md`) ve bu standarttan farklıysa, değişiklik yapmadan önce kullanıcıya sor.

## 1. Önce sor: bu iş trigger'da mı olmalı?
Trigger **yalnızca** şu işler için kullanılır:
- Audit kolonlarını doldurmak (`CREATED_AT`, `CREATED_BY`, `UPDATED_AT`, `UPDATED_BY`)
- Değişiklik geçmişi / history tablosuna kayıt
- Hangi uygulama yazarsa yazsın **her zaman** geçerli olması gereken ve constraint ile ifade edilemeyen veri bütünlüğü kuralı

Şunlar trigger'da **yapılmaz**, uygulama veya package'ta yapılır:
- İş akışı (sipariş onaylanınca stok düş, fatura oluştur vb.)
- Başka iş tablolarına zincirleme INSERT/UPDATE/DELETE
- Dış sistem çağrısı (HTTP, mail, kuyruk)
- ID üretmek: Oracle 12c+ için `GENERATED BY DEFAULT ON NULL AS IDENTITY` veya `DEFAULT SEQ_X.NEXTVAL` kullan (bkz. `oracle-ddl-script`)

Bir iş bu listede yoksa trigger yazma; analiz/karar adımında bunu kullanıcıya sor.

## 2. İsimlendirme
`TRG_<TABLO>_<ZAMAN><OLAY>` — tümü büyük harf, en fazla 30 karakter.

| Parça | Değerler |
|---|---|
| ZAMAN | `B` = BEFORE, `A` = AFTER, `IO` = INSTEAD OF |
| OLAY | `I` = INSERT, `U` = UPDATE, `D` = DELETE (birleşik: `IU`, `IUD`) |
| Compound trigger | `TRG_<TABLO>_CMP` |

Örnekler: `TRG_ORDERS_BIU`, `TRG_ORDERS_AIUD`, `TRG_ORDER_LINES_CMP`.
Tablo adı 30 karakter sınırını aşırıyorsa projede kullanılan tablo kısaltmasını kullan.

## 3. Yapı kuralları
- Bir tabloda aynı ZAMAN + OLAY için **tek** trigger olur. Yeni bir kural ekleniyorsa mevcut trigger'a eklenir; ikinci trigger açılmaz.
- Trigger gövdesi **ince** olur: 15 satırı geçen mantık `PKG_<TABLO>_TRG` package'ına procedure olarak taşınır, trigger yalnızca çağırır.
- Yalnızca ilgili kolon değiştiğinde çalışması gerekiyorsa `UPDATE OF <KOLON>` veya `UPDATING('<KOLON>')` ile sınırla.
- UPDATE'te "değer değişti mi" kontrolü NULL'a dayanıklı yazılır:
  ```sql
  IF (:OLD.STATUS <> :NEW.STATUS)
     OR (:OLD.STATUS IS NULL AND :NEW.STATUS IS NOT NULL)
     OR (:OLD.STATUS IS NOT NULL AND :NEW.STATUS IS NULL) THEN
  ```
- İş hatası `RAISE_APPLICATION_ERROR(-20xxx, 'Açıklayıcı mesaj')` ile fırlatılır; projenin hata kodu aralığını kullan (bkz. `oracle-plsql`).
- Zaman damgası kolon tipine uygun: `TIMESTAMP` kolona `SYSTIMESTAMP`, `DATE` kolona `SYSDATE`.
- Kullanıcı bilgisi: uygulamalar tek DB kullanıcısıyla bağlandığı için `USER` tek başına anlamsızdır.
  Önce uygulamanın gönderdiği değer, sonra `SYS_CONTEXT('USERENV', 'CLIENT_IDENTIFIER')`, en son `USER` kullanılır.

## 4. Yasaklar
| Yasak | Neden |
|---|---|
| `COMMIT` / `ROLLBACK` | ORA-04092; transaction'ı uygulama yönetir. (Tek istisna: `PRAGMA AUTONOMOUS_TRANSACTION` ile çalışan hata log procedure'ü çağırmak.) |
| Satır seviyesi trigger'da tetikleyen tabloyu SELECT/UPDATE etmek | ORA-04091 mutating table. Gerekiyorsa **compound trigger** (Şablon C). |
| DDL (`CREATE`, `ALTER`, `EXECUTE IMMEDIATE` ile DDL) | Örtük COMMIT yapar |
| `WHEN OTHERS THEN NULL` | Hatayı yutar, veri sessizce bozulur |
| Dış çağrı (`UTL_HTTP`, `UTL_MAIL`, DB link üzerinden yazma) | Yavaşlık, rollback'te geri alınamayan yan etki |
| Aynı ZAMAN+OLAY için ikinci trigger | Çalışma sırası belirsizleşir |

## 5. Şablonlar

### Şablon A — Audit kolonları
```sql
CREATE OR REPLACE TRIGGER TRG_ORDERS_BIU
BEFORE INSERT OR UPDATE ON ORDERS
FOR EACH ROW
BEGIN
  IF INSERTING THEN
    :NEW.CREATED_AT := SYSTIMESTAMP;
    :NEW.CREATED_BY := COALESCE(:NEW.CREATED_BY, SYS_CONTEXT('USERENV', 'CLIENT_IDENTIFIER'), USER);
  ELSE
    -- Oluşturma bilgisi güncellemede değiştirilemez
    :NEW.CREATED_AT := :OLD.CREATED_AT;
    :NEW.CREATED_BY := :OLD.CREATED_BY;
  END IF;

  :NEW.UPDATED_AT := SYSTIMESTAMP;
  :NEW.UPDATED_BY := COALESCE(:NEW.UPDATED_BY, SYS_CONTEXT('USERENV', 'CLIENT_IDENTIFIER'), USER);
END TRG_ORDERS_BIU;
/
```

### Şablon B — History tablosu
History tablosu adı `<TABLO>_HIST`; kolonları: `HIST_ID`, `OPERATION` (`I`/`U`/`D`), `CHANGED_AT`, `CHANGED_BY` + izlenen kolonların eski/yeni değerleri.
```sql
CREATE OR REPLACE TRIGGER TRG_ORDERS_AIUD
AFTER INSERT OR UPDATE OR DELETE ON ORDERS
FOR EACH ROW
DECLARE
  v_operation CHAR(1);
BEGIN
  v_operation := CASE WHEN INSERTING THEN 'I' WHEN UPDATING THEN 'U' ELSE 'D' END;

  PKG_ORDERS_TRG.P_LOG_HISTORY(
    p_operation  => v_operation,
    p_order_id   => COALESCE(:NEW.ID, :OLD.ID),
    p_old_status => :OLD.STATUS,
    p_new_status => :NEW.STATUS
  );
END TRG_ORDERS_AIUD;
/
```

### Şablon C — Compound trigger (mutating table çözümü)
Satır değişikliğinden sonra **aynı tabloyu** okuyan bir hesap gerekiyorsa (örn. sipariş satırları değişince sipariş toplamını yeniden hesapla):
```sql
CREATE OR REPLACE TRIGGER TRG_ORDER_LINES_CMP
FOR INSERT OR UPDATE OR DELETE ON ORDER_LINES
COMPOUND TRIGGER

  TYPE t_id_tab IS TABLE OF ORDER_LINES.ORDER_ID%TYPE INDEX BY PLS_INTEGER;
  g_order_ids t_id_tab;

  AFTER EACH ROW IS
  BEGIN
    -- Satır seviyesinde yalnızca ID topla; tabloyu burada okuma
    g_order_ids(g_order_ids.COUNT + 1) := COALESCE(:NEW.ORDER_ID, :OLD.ORDER_ID);
  END AFTER EACH ROW;

  AFTER STATEMENT IS
  BEGIN
    -- Statement seviyesinde tablo okunabilir
    FOR i IN 1 .. g_order_ids.COUNT LOOP
      PKG_ORDERS_TRG.P_RECALC_TOTAL(p_order_id => g_order_ids(i));
    END LOOP;
  END AFTER STATEMENT;

END TRG_ORDER_LINES_CMP;
/
```

## 6. Script dosyası
- Her trigger kendi dosyasında, `CREATE OR REPLACE TRIGGER` ile (tekrar çalıştırılabilir), sonda `/`.
- Rollback script'i: `DROP TRIGGER TRG_...;` (trigger önceden varsa ve değiştiriliyorsa rollback, **önceki sürümün** `CREATE OR REPLACE` metnidir).
- Dosya adı ve klasörü `oracle-ddl-script` standardına göre.
- Script'in başına kısa bir yorum: ne yapar, hangi task için, hangi kolonları etkiler.

## Kontrol listesi
Zorunlu:
- [ ] İş gerçekten trigger'a uygun (Bölüm 1)
- [ ] İsim `TRG_<TABLO>_<ZAMAN><OLAY>`, ≤ 30 karakter
- [ ] Aynı ZAMAN+OLAY için ikinci trigger yok
- [ ] COMMIT/ROLLBACK/DDL yok
- [ ] Satır seviyesinde tetikleyen tablo okunmuyor/yazılmıyor (gerekirse compound)
- [ ] `WHEN OTHERS THEN NULL` yok
- [ ] UPDATE değişim kontrolü NULL'a dayanıklı
- [ ] Rollback script'i var

Tavsiye:
- [ ] Gövde 15 satırı geçiyorsa mantık package'ta
- [ ] `UPDATE OF` ile gereksiz tetiklenme sınırlanmış
- [ ] Script başında açıklama yorumu var
